## Overview

This document records the frozen core contract for Readest enhanced features Phase 0. All interfaces are defined in `enhanced/core/` and have no dependencies on Readest internal paths, React, DOM APIs, or Tauri.

## Contract Files

- **models.ts** - Domain models and DTOs
- **ports.ts** - Port interface definitions with error handling

## Port Interfaces

### 1. ReaderPort

**Purpose**: Access to reading view, text selection, and content positioning.

**Evidence Sources**:
- `access-points.md` sections 1 (Text Selection) and 2 (CFI Positioning)
- `decision-draft.md` section 1 items 1, 2, 5
- `apps/readest-app/src/types/view.ts:50,91-92,98`
- `apps/readest-app/src/app/reader/hooks/useTextSelector.ts:186,227,296,353,394`

**Methods**:
- `getTextSelection(bookHash)` - Get current text selection with CFI
- `resolveLocation(bookHash, cfi)` - Resolve CFI to content and position
- `getCurrentLocation(bookHash)` - Get current reading position CFI
- `getReadingProgress(bookHash)` - Get progress percentage and page info
- `getCurrentBookHash()` - Get active book identifier
- `goToLocation(bookHash, cfi)` - Navigate to CFI position

**Design Decisions**:
- Per `decision-draft.md` section 5.4: Explicit bookHash parameter for multi-book support
- Per `decision-draft.md` section 5.2: Phase 0 only current page text extraction (no full book text)
- Per `decision-draft.md` section 2 item 1: CFI as sole position identifier

**Constraints**:
- CFI strings are version-locked to book content (re-import may invalidate CFI)
- Cross-iframe data must be JSON-serializable (no DOM Range objects)
- Only rendered pages are accessible (unloaded chapters require navigation first)

### 2. LibraryPort

**Purpose**: Book import and metadata access.

**Evidence Sources**:
- `access-points.md` section 3 (Library Import)
- `decision-draft.md` section 1.3
- `apps/readest-app/src/services/bookService.ts:461`
- `apps/readest-app/src/services/appService.ts:406-411`

**Methods**:
- `importBook(file, options)` - Import EPUB/PDF/TXT/MOBI file
- `getBookMetadata(bookHash)` - Get metadata by hash
- `listBooks()` - List all library books

**Design Decisions**:
- Per `access-points.md` section 3.3: Accepts File object or path string
- Per `access-points.md` section 3.1: Supports transient mode for "Open with" scenarios
- Deduplication by file hash and metadata hash handled by upstream

**Constraints**:
- Supported formats: EPUB, PDF, TXT, MOBI only
- Tauri platform uses native parsers, Web platform uses foliate-js
- File input can be local path, `content://` URI (Android), or HTTP URL

**Evidence Sources**:

**Design Decisions**:

**Constraints**:

## Error Handling

All port methods returning `Promise<T>` use structured errors:

```typescript
interface PortError {
  code: string;
  message: string;
  cause?: unknown;
}
```

**Standard Error Codes**:
- `BOOK_NOT_FOUND` - Invalid book hash
- `CFI_INVALID` - Malformed or unresolvable CFI
- `TTS_ENGINE_UNAVAILABLE` - TTS client initialization failed
- `IMPORT_FAILED` - Book file parsing error
- `UNSUPPORTED_FORMAT` - File format not EPUB/PDF/TXT/MOBI
- `EUDIC_API_ERROR` - External Eudic API failure
- `PERMISSION_DENIED` - User has not authorized access

**Evidence**: `decision-draft.md` section 2 "强制要求" item 5

## Capabilities Included

### Confirmed from P0 Inventory

1. **Text Selection** - `access-points.md` section 1
   - Get selection from iframe documents via `getContents()` + `doc.getSelection()`
   - Convert to TextSelection with CFI via `view.getCFI()`

2. **CFI Positioning** - `access-points.md` section 2
   - Bidirectional CFI conversion: `getCFI()` and `resolveCFI()`
   - Navigate to CFI positions via `view.goTo()`

3. **Book Import** - `access-points.md` section 3
   - Import via `appService.importBook()` with deduplication
   - Supports File objects and path strings
   - Handles EPUB/PDF/TXT/MOBI formats

4. **TTS Control** - `access-points.md` section 4
   - Playback control via `TTSController`
   - State monitoring via `eventDispatcher`
   - Cross-platform: Web (Edge/WebSpeech), Tauri native

5. **Reading Progress** - `decision-draft.md` section 1.5
   - Progress calculation via `getCFIProgress()`
   - Page count and estimated time

## Capabilities NOT Included

Per `decision-draft.md` section 3 "明确不纳入的能力":

### 1. Android Background Tasks

**Reason**: No `WorkManager` or `JobScheduler` found in codebase  
**Evidence**: `access-points.md` section 6.1  
**Impact**: Enhanced features cannot rely on background sync or scheduled downloads

---

### 2. Remote Push Notifications

**Reason**: `POST_NOTIFICATIONS` permission declared but no FCM integration  
**Evidence**: `access-points.md` section 6.3  
**Impact**: No remote notification capability (only foreground MediaPlaybackService notifications)

---

### 3. Native File System Deep Access

**Reason**: Readest uses Tauri FileSystem API with sandbox restrictions  
**Evidence**: `decision-draft.md` section 3.3  
**Impact**: Enhanced features access content via ports, not direct file reads

---

### 4. Foliate-js Rendering Modifications

**Reason**: foliate-js is Git submodule, changes require upstream merge  
**Evidence**: `decision-draft.md` section 3.4, submodule pointer `98b82a517`  
**Impact**: No custom renderer injection (CSS injection via `view.setStyles()` allowed)

---

### 5. Full Book Text Extraction (Phase 0)

**Reason**: Phase 0 privacy limitation - only current page extraction  
**Evidence**: `decision-draft.md` section 5.2  
**Impact**: AI summaries requiring full text deferred to Phase 1  
**Alternative**: Manual chapter-by-chapter extraction via `book.load(section.id)`

---

### 6. TTS Audio Stream Manipulation (Phase 0)

**Reason**: Phase 0 scope limitation  
**Evidence**: `decision-draft.md` section 5.3  
**Impact**: No pitch/speed modification or background music mixing  
**Alternative**: Control playback only via play/pause/stop

## Open Questions Resolved

Per `decision-draft.md` section 5, these were resolved with recommended approaches:

### 1. Port Deployment Location

**Resolution**: Interface-only design, deployment decided by `workspace-bootstrap`  
**Rationale**: Decouple contract definition from implementation strategy

---

### 2. User Data Privacy Boundary

**Resolution**: Phase 0 only current page text via `getTextSelection()`  
**Rationale**: Full book extraction deferred until permission model complete

---

### 3. TTS Audio Stream Ownership

**Resolution**: Phase 0 playback control only (no audio stream access)  
**Rationale**: Audio manipulation deferred until requirements clarified

---

### 4. Multi-Book Concurrency

**Resolution**: Explicit `bookHash` parameter + `getCurrentBookHash()` helper  
**Rationale**: Avoid implicit state, but provide convenience for single-book use

---

### 5. Offline Capability

**Resolution**: All read operations local, only TTS synthesis may be online  
**Rationale**: Offline-first design for core reading features
